# Data and models

## Official sources and the paper window

Obtain Block Transaction archives from the [XBlock official directory](https://xblock.pro/xblock-eth.html). The paper period is covered by [`18750000to18999999_BlockTransaction.zip`](https://zhengpeilin.com/download.php?file=18750000to18999999_BlockTransaction.zip). `./arbor data paper` displays these links and the preparation command.

The paper reference measurements used **8,840,117 accepted historical transactions** and **979,572 accepted test transactions**. The history was filtered from a fixed 9-million-row export; the test used the accepted part of the next fixed 1-million-row evaluation prefix. Their boundaries and hashes are retained in [`configs/paper-source.json`](../configs/paper-source.json).

The historical interval is Unix time `1702140995..1704198515`; the test interval is `1704198515..1704445631`. Equal boundary timestamps are allowed: split membership follows source-record positions. There are 4,412,554 historical accounts and 418,127 newly encountered test accounts. Initial synthetic balances and nonces are generated by `history/layout.py`, not obtained from a live Ethereum account-state snapshot.

Exact test CSV SHA256:
`a09949047e1c10b3cd304acec350859526880b6128a68b30c630c8a3d875d339`.

The reference history CSV uses exact integer values and CRLF records. Reference identities describe the historical exports; a newly prepared XBlock window receives its own input hashes, counts and source boundaries. The commands below reproduce the method workflow on that local window.

The reference history spans blocks 18,750,000–18,919,698; the test spans 18,919,698–18,940,083. Original archive row positions were not retained by the historical export; new imports record the archive and row for every accepted transaction.

## Prepare a local experiment window

Save the downloaded archive under `data/raw/`, then run:

```bash
./arbor data xblock \
  --source data/raw/18750000to18999999_BlockTransaction.zip \
  --history-count 8840117 --test-count 979572 --output data/paper
./arbor run full
```

One command streams the Block Transaction CSV in each ZIP, filters rows, takes the requested history followed by test, and builds the dataset consumed by the runner. Counts refer to accepted transactions. Inputs can be CSV files or multiple consecutive archives passed in order after `--source`. Change the two counts to select a smaller window. The 18-column source header is:

```text
blockNumber timestamp transactionHash from to toCreate fromIsContract toIsContract
value gasLimit gasPrice gasUsed callingFunction isError eip2718type baseFeePerGas
maxFeePerGas maxPriorityFeePerGas
```

Only non-contract endpoints, valid 40-hex addresses, distinct sender/recipient and nonnegative integer values are accepted. Values use exact integers; valid duplicates remain in order. Preparation rejects timestamp regression and builds IDs by first appearance. `source_file.npy` and `source_row.npy` index the source manifest and the one-based archive data row. `raw_row.npy` indexes the intermediate accepted CSV from zero.

For existing headerless exports, use `./arbor data prepare --history history.csv --test test.csv --output data/custom`. This input uses the same field order; optional `history.origin.csv` and `test.origin.csv` sidecars carry archive/row identifiers. The output includes `manifest.json`, ordered history/test CSVs, dense-ID arrays, an address namespace and initial forest records. History graphs and layouts are built when an experiment starts.

Datasets are downloaded from XBlock and follow its source terms. This repository distributes the processing code and reference metadata.

## Frozen models

`models/fusion.json` contains the historical fusion weights. `models/admission.json` contains the 20-feature linear cost ranker, normalizer, candidate contract and tie tolerance. Original artifact identities are recorded below and in `docs/source_provenance.json`.

Original admission artifact:
`f03d32a81f77f805d5fe0c3c018112ea246abc36c563c5eb7856b81f9b59859b`.

Original fusion artifact:
`c9cb416989bdb6880c32e46a0d367b3899a336558afe8e333c0e2b6e46dfbea8`.

The ranker normalizes training features, predicts within-candidate cost differences, and selects the first candidate within `1e-6` of the minimum. Candidates use the fixed seed-43 counter generator and retain sampling order. `scripts/check_parity.py` checks the Python/Go interface.

## Explicit training

Fusion training uses prefixes at historical days 12 and 16 and labels from their next historical day. Admission sample preparation uses the early fusion fit (days 8 and 12) for days 13–16, then the supplied later fusion fit for days 17–20. Fixed service calendars under `configs/training/` define the five training scene families. Candidate labels come from full-drain counterfactual continuations, checked against the backbone continuation; this is offline training simulation, not a native performance measurement.

Admission fitting uses equal day/scene/point weights, training-only normalization and ridge coefficient 0.01. Each training directory retains prepared windows, label records, exported model and hashes. `--small` selects short synthetic historical windows for validation. The default experiment path never trains, and neither command overwrites the frozen model.

Select exported models with `arbor run ... --fusion-model <path> --admission-model <path>`. Each run snapshots the selected files and records their hashes; the fusion model also participates in the layout cache identity.
